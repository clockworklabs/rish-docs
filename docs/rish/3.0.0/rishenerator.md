Rishenerator does _a lot_ under the hood. It's not only a source generator but also a source analyzer and it improves code safety drastically by preventing us from shooting ourselves on the foot. For example:
- it forces Props and Structs to have the `RishValueType` attribute;
- it prevents creating `Element`, `Children`, `RishList`, `ClassName` or any other internally managed type outside the scope of a `ManagedContext`; and
- it prevents the creation of `ManagedContext` in wrong ways or contexts.

As a source generator, it generates a lot of otherwise boilerplate and very error-prone code:
- For every UI Element (VisualElement or RishElement), it generates `Create` factory methods, with all the necessary arguments matching the Props and other inputs.
- For every value type with the `RishValueType` attribute, it generates Comparers and code to handle reference dependencies.
- For delegate types in Props, it generates methods we can call.
- For fields in State, it generates Setters (that are optimized for fast memory management).

Once again, you should use Rishenerator. The following are examples of auto-generated source to better understand what's going on under the hood and how all these different systems work. Do not use this code as a reference or a tutorial on how to not use Rishenerator.

The only thing you need to keep in mind is that some names are reserved and shouldn't be used in Props fields to avoid overlaps with other arguments in the Create methods:
- `key` is always reserved. Every RishElement and VisualElement Create methods will have a `key` argument.
- `name`, `className`, `style` are reserved for VisualElements and RishElements with expanded DOMDescriptor.
- `children` is reserved for VisualElements.
